## Principal-engineer review: follow-ups and how to make each design more efficient

- **A1 / A2:** XOR (or the sum formula in `long`) finds one missing number; for two missing numbers split the range by the lowest set bit of `a ^ b`. Index marking only works because values fit the index range; otherwise use a `BitSet` or a hash set, and say what you trade (O(1) space vs a mutated input, which is unsafe for shared or read-only arrays and for concurrent readers). `firstUniqChar` over Unicode needs a `HashMap`/`LinkedHashMap` of counts, or `String.codePoints()`. Binary search: the half-open `[lo, hi)` form has no off-by-one, `lo + (hi - lo) / 2` avoids overflow, lower/upper bound cover insert, first/last and count-of-occurrences, and rotated-array search with duplicates degrades to O(n) in the worst case (`hi--` when `a[mid] == a[hi]`). The same idea works on any monotone predicate (search on the answer).
- **B1:** `groupingBy(f, TreeMap::new, downstream)` fixes the iteration order while grouping; `summingLong` instead of `summingInt` is the overflow fix; `collectingAndThen(minBy(c), Optional::get)` is the standard "best element per group". A single pass with several downstreams (`teeing`, or one `Collector` that fills a small accumulator record) beats running `topCustomers` after `totalByCustomer` on big inputs; a bounded min-heap makes top-k O(m log k). Streams are not free: for hot paths a plain loop avoids boxing (`mapToLong`, `IntStream`).
- **C1:** Every sliding window has an invariant plus a repair step; each index enters and leaves once, so O(n). `longestUnique` with a last-seen array is one pass with no inner loop (the `max(l, last + 1)` form guards against stale entries - the `"abba"` test); for a huge alphabet use a `HashMap<Character,Integer>`. For `shortestSubarrayAtLeast` positivity is what makes the window monotone; with negative numbers you need prefix sums and a monotonic deque (the hard follow-up: "shortest subarray with sum at least K"). Related: minimum window substring, permutation in string, longest subarray with at most k distinct.
- **C2:** `wordBreak` limited to the longest word is O(n * L) lookups with substring hashing O(L) each; a trie removes the hashing and also lets you enumerate all sentences (backtracking with memo, output can be exponential: say so). `minPathSum` keeps one row; the path itself needs the full table or Hirschberg-style reconstruction. Palindromic substrings: expand-around-centre is O(n^2) with O(1) space; Manacher is O(n); the 2D boolean DP uses O(n^2) memory and is the weakest option here. Follow-ups: longest palindromic substring, minimum cuts for a palindrome partition, unique paths with obstacles, dungeon game (DP from the end).
- **D1:** A strictly increasing path cannot repeat a cell, so the "graph" is a DAG and the answer is its longest path. Memoised DFS is O(mn) but recursion depth reaches mn; peeling the DAG by out-degree (Kahn from the sinks) does the same work with arrays and no stack. Layers of the peel = longest path length. Alternatives: sort cells by value and run DP in that order (O(mn log mn), simplest to prove); iterative DFS with an explicit stack and a state array. Follow-ups: count the number of longest paths, allow non-decreasing steps (cycles appear: need SCC), 3D grid.
- **E:** Model transitions in the enum with an exhaustive `switch` so a new status cannot be forgotten, and keep the rule in one place, not in controllers. `@Version` turns a lost update into `ObjectOptimisticLockingFailureException` at flush (so it can surface after your method returned, inside the commit): map it to 409 and let the client reload; for hot rows add a retry (`@Retryable`) around the whole transaction. Bulk JPQL updates bypass entity callbacks, `@Version` and the persistence context: they are fast but do not bump the version, so a concurrent edit is not detected - add `t.version = t.version + 1` to the update if that matters, and `clearAutomatically` to avoid stale reads. `Slice` skips the `count(*)`; for deep pages use keyset pagination `(createdAt, id) < (?, ?)`. The `(:p is null or col = :p)` pattern is simple but can defeat index use and produce poor plans on PostgreSQL (typed-null binding too): switch to Specifications/Criteria or `QueryDSL` when filters grow. Custom constraints should be stateless and null-tolerant; compose with `@NotNull`. A `@Scheduled` job runs on every instance: guard it with a distributed lock (ShedLock) or a leader, and make the work idempotent.
- **F1 / G:** Split control plane (CRUD, audit, approvals, stored in a relational DB) from data plane (evaluation). Evaluate locally in an SDK from a cached ruleset so a flag service outage costs nothing: ship the full ruleset per environment (5 000 flags is a few MB) as a versioned, gzip-ed blob behind a CDN, poll with `ETag` every few seconds or push invalidations over SSE/long-poll, keep the last good copy on disk, and fall back to a coded default. Evaluation is pure CPU: no network call per check, which is how 2 M evaluations/s become trivial. Bucketing: hash `(flagKey, userId)` with a mixing function (murmur3) so users are sticky, flags independent, and ramping 10 -> 50 % only adds users; salt per experiment to re-randomise. Never pass the full ruleset to untrusted clients (it leaks targeting): evaluate server-side and send results. Roll out flag changes themselves gradually, with a kill switch that is checked first and auditable. LLD: copy-on-write snapshot gives lock-free reads and atomic multi-flag updates; `evaluateAll` on one snapshot avoids torn reads between related flags; `Flag` is a value object with deep immutable copies; exposure logging should be sampled and async, never on the request path. Debt control: owner and expiry date per flag, alerts on flags older than 90 days, and a lint that finds dead flags in code.
- **F2:** One ingest API with an idempotency key (`eventId + userId + type`) deduplicated in Redis/DB with a TTL; a router applies preferences, quiet hours and per-user throttles and writes one task per channel to a queue per `(channel, priority)`; separate worker pools and quotas keep a marketing burst from delaying OTPs. Broadcast to 100 M users is a fan-out job that pages through the user table and emits tasks at a controlled rate, with a global pause button. Providers sit behind an interface with timeouts, circuit breakers and weighted failover; delivery receipts arrive by webhook and update a status table (partitioned by time, short retention). Retries use exponential backoff with jitter and a dead-letter queue; time-sensitive messages carry an expiry so a late SMS is dropped rather than sent. Preferences are read-heavy: cache them per user with write-through invalidation. Watch for duplicate sends after a worker crash (at-least-once delivery: dedupe at the provider call with the idempotency key where the provider supports it).
- **H1:** rules behind each result: JLS 8.3.3 and 15.12 (fields and static methods bind to the static type, instance methods dispatch on the runtime type, overloads are chosen at compile time), 14.20.3 (try-with-resources: reverse close order, `addSuppressed`), `String.split` Javadoc (trailing empty strings removed with limit 0, `"".split(",")` is `[""]`), `ArrayList` iterator behaviour (`hasNext` is `cursor != size`; `next` checks `modCount`), `subList` fail-fast views, `PriorityQueue(Collection)` heapify (array order is not sorted order), `TreeSet` uses its comparator for equality, stream laziness and the single-use rule, `Collectors.toMap` duplicate-key rule, JLS 5.1.3 (narrowing keeps low bits), 5.1.3 for floating-point to integral saturation, `Math.round` = `floor(x + 0.5)`, JLS 15.17.2/15.19 (division truncates, `%` has the dividend's sign, `>>` vs `>>>`), `Double.equals` vs `==` for `NaN` and `-0.0`.
- **H2:** JDK proxies need an interface; Spring falls back to CGLIB (a subclass proxy: no `final` classes/methods, needs a visible constructor) for classes, and Spring Boot defaults to CGLIB (`spring.aop.proxy-target-class=true`). Self-invocation (`this.other()`) bypasses the proxy, which is why a `@Transactional` method called from the same class does nothing; fix with a separate bean or self-injection. Unwrap `InvocationTargetException` and let the handler throw the real cause: a checked exception not declared by the interface becomes `UndeclaredThrowableException`. `computeIfAbsent` gives single-flight per key but holds a bin lock for the duration, so keep the loader short or store `CompletableFuture`s (which also lets failures be evicted). Unbounded memo maps leak: add a size bound and TTL (Caffeine) in real code. Retries need idempotent targets, a backoff with jitter and a retry budget, or they amplify an outage; also decide which exceptions are transient.
